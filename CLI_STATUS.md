# CLI Implementation Status

## Implemented

- **Session management** — create, resume, list (meta.json + session.jsonl); lazy creation — session dir only written on first user message, not on startup
- **Event log** — append-only JSONL, stream-cleanup of content_start/delta after content_end; strictly increasing IDs (`remove_streaming_events` returns max seen id; `append_event` accepts `min_id` floor to prevent ID regression after removal)
- **Interactive REPL** — multi-turn chat, `> ` prompt, Ctrl+C to stop/exit
- **Rich user input** (`cli/input.py`) — `\` + Enter multi-line continuation (`... ` prompt); bulk paste detection (80 ms silence window, cross-platform `msvcrt`/`select`); immediate `[pasted N lines]` echo followed by `... ` prompt for optional follow-up instructions; paste and `\` continuation are fully composable; image path detection stub (Part 3 pending); falls back to plain `input()` in non-TTY / test environments
- **Non-interactive mode** — `--prompt` and `--prompt-file` flags, stdout output, stderr for status
- **Renderer** — streaming text to stdout; tool calls displayed with emoji badge (`⚡` auto/whitelisted, `⚠️` needs approval, `❗` needs human/outside-CWD, `❌` error/denied, `✅` approved); multi-line aligned `key = value` arg display (truncated for system-approved, full for human approval); multiline values rendered with continuation lines indented to align under the first value character, no `repr()` quoting; blank line separator before LLM response after tool block; shell tool output printed indented under tool block; denials printed once only (no duplicate error line); `show_output` flag on `Tool` base class controls whether result content is printed (default `False`, `True` for `pwsh`/`bash`); multi-line tool results and errors fully indented — all lines after the first are prefixed with 5-space indent so output never resets to column 0
- **Slash commands** — `/agent`, `/model`, `/project` (immediate, writes meta.json + system_hint), `/skills` (list skills), `/<skill_name>` (load skill into context), `/compact`, `/usage`, `/archive` (exit + archive session), `/help`, `/exit`, `/quit`
- **system_hint events** — logged when agent/model/project changes mid-session; injected as UserMessage into LLM context
- **Approval** — three-state (`False`=auto, `True`=whitelist→human, `"human"`=always human); `Y/p/d/n` prompt; deny prompts for optional reason fed back to LLM as tool result; auto-deny in non-interactive mode
- **Approval whitelist** — `.quack-whitelist.yaml` (project, always resolved from session CWD) + `~/.config/quack-norris/whitelist.yaml` (global); pattern picker with session/project/global scope; glob matching (`*` / `**`); whitelist reloads on `/project` switch
- **Dynamic approval predicates** — `@tool(needs_approval=fn)` allows per-call approval decisions based on arguments (e.g. `file_view` auto-executes inside CWD, escalates outside)
- **Overflow dir auto-approval** — `make_file_tools(get_cwd, session_id)` makes all file tools (`file_view`, `file_write`, `file_str_replace`, `file_move`, `file_delete`) auto-execute without approval when every path argument resolves inside the *current* session's overflow dir (`session_dir(session_id)/overflow`, via `overflow_dir()` in `cli/session.py` — the same dir `make_overflow_sink` spills oversized tool output into), so the agent can freely read/write/delete its own scratch data; sibling sessions, `meta.json` and `session.jsonl` are **not** exempt, `file_move` requires *both* source and destination inside the dir, and omitting `session_id` exempts nothing
- **Session menu** — list/select from existing sessions on startup
- **`--resume <id>`** — skip menu, jump to specific session; supports prefix matching: unique prefix resumes directly, ambiguous/no match falls through to the session picker
- **`--project <dir>`** — start directly in a specified project directory
- **`--archive-on-exit`** — archive session on clean exit
- **History reconstruction** — rebuild ChatMessage history from session.jsonl on resume (`build_chat_history()` / `replay_messages()` in `cli/context.py`); the replay is message-for-message faithful to what the agent loop held in memory: one `AssistantMessage` per loop iteration (from `content_end`), its tool calls attached from `tool_call_start` events with their real arguments, results directly after it, and injected nudges replayed from `system_hint` — this fidelity is what makes checkpoint offsets meaningful; the newest `checkpoint` event is applied by slicing (`[CheckpointMessage] + raw[replaces:]`); history display on resume uses the same `Renderer` as live output — tool calls replayed as `ToolCallOutput` (⚡ badge + indented args), tool results replayed as `ToolResultOutput` (❌ on error, indented content on success), assistant text replayed as `TextOutput`, so the resumed session view is visually identical to live rendering; `show_output` persisted in `tool_call_result` events so history replay respects it — `file_view` and other silent tools don't dump their output on resume, only `pwsh`/`bash`/background tools (which have `show_output=True`) do; old events without the field default to `False`
- **Context management (core)** — `core/context.py` owns the whole policy and runs inside the agent loop before *every* LLM call, not once per user turn: it measures system prompt + tool schemas + history, redacts tool output older than the newest `verbatim` share of the window, and only if utilisation is still at/over `checkpoint_at` summarises the oldest `checkpoint_reduction_rate` share of the history into a `CheckpointMessage`; the module is storage-agnostic (pure `list[ChatMessage]` in, `CheckpointOutput` out) so the same policy applies to subagents, which never touch the session log
- **Checkpoints** — a `CheckpointMessage` is a `UserMessage` subclass (providers see `role: "user"`) carrying `replaced_count`, the number of *raw replayed* messages it stands in for; checkpoints subsume each other (a later one folds in the earlier summary and inherits its count), so reconstruction only ever applies the newest; persisted as `checkpoint` events with `summary`, `replaces`, `trigger`, `tokens_before`/`tokens_after`; rendered live and on resume as `◆ checkpoint — N messages summarised`
- **Safe cut points** — checkpoint cuts are rounded forward past `ToolResultMessage`s so an assistant message and all of its results are always dropped as one block; cutting mid-block would leave a result whose `tool_call_id` no longer appears in the history, which providers reject outright; a cut always leaves at least one message
- **Tool output redaction** — tool results outside the verbatim window are replaced in memory with `[REDACTED TO SAVE CONTEXT, repeat the operation if the output is needed, e.g. re-read the file]`; user/assistant text is never touched, the message is never removed (so tool-call ids stay matched), `session.jsonl` keeps the full record, and the pass is idempotent — this alone keeps most sessions under the checkpoint threshold indefinitely
- **Per-result token cap** — a single tool result is clipped to `context_management.max_tool_output` tokens before it reaches the agent, the renderer or the log, keeping head *and* tail (stack traces and exit codes live at the end) with a notice in between stating how much was removed; the CLI spills the full text to `<session>/overflow/<id>.txt` and the notice points the agent at it
- **Checkpoint sizing by reduction rate** — a checkpoint drops `checkpoint_reduction_rate` (default 0.5) of the *history*, not down to a fraction of the *window*: the cut is `history_tokens * (1 - rate)` less a summary allowance, so a checkpoint always removes a predictable share of what is actually there regardless of window size or system-prompt/tool-schema overhead, and `/compact` therefore always does something on a history of any size; parsed value is clamped to 0.95 since a rate of 1.0 would summarise away the newest message too
- **`truncation_allowed` on tools** — `@tool(truncation_allowed=False)` exempts a tool's result from the `max_tool_output` cap (default `True`); set on `use_skill`, whose output is instructions rather than data — a clipped skill is worse than no skill because the model cannot tell it is following half a procedure; the flag lives on `Tool`, is bound onto `ToolCallRequest` at stream time next to `show_output`, and is read by the agent loop before capping; exempt output is still redacted wholesale once it ages out of the verbatim window, which is safe because the model can reload the skill
- **`/compact`** — forces a checkpoint immediately regardless of utilisation (same code path with `checkpoint_at` dropped to 0), and reports messages summarised and the token delta
- **`/usage` context reporting** — applies the same redaction pass the next LLM call would before measuring, so `active context` is what will actually be sent rather than the raw replayed history (the two diverge most right after a resume, where the log replays every tool result in full); reports `tool output N of M results redacted` as a *state* rather than a per-call delta, since the idempotent strip pass would otherwise report the full set once and zero on every call after
- **Context management config** — `context_management.enabled`, `.verbatim` (0.30), `.checkpoint_at` (0.80), `.checkpoint_reduction_rate` (0.5), `.max_tool_output` (4096 tokens), `.summarizer_model` (falls back to the conversation model) in `config.yaml`/`llms.yaml` (`ContextManagementConfig` in `core/llm/config.py`, exposed via `LLM.context_config()`); `verbatim` and `checkpoint_at` are fractions of the model's context window (`context_window` per `llms:` group, defaulting to 128k — set it or the thresholds measure against the wrong size); a startup warning fires when `max_tool_output` exceeds the verbatim window, since one result could then fill all of short-term memory
- **`SlashContext`** — mutable context object (`session_id`, `meta`, `chat_history`, `model`, `system_prompt`, `whitelist`, `archive_on_exit`, `system_prompt_parts`) passed to all slash handlers; enables LLM access and history mutation from any slash command; `archive_on_exit` flag set by `/archive` and read back by the call site to trigger archiving after the loop exits; `system_prompt_parts` is the same list instance passed to `_run_turn`, so skill content appended by `/<skill_name>` is picked up on the next agent turn
- **LLM config** — `LLM.setup()` merges the global `~/.config/quack-norris/config.yaml`/`llms.yaml` (base) with a project-local `config.yaml`/`llms.yaml` in cwd (or `--config` path) layered on top; local doesn't need to be complete — `defaults`/`context_management` are merged key-by-key, `llms:` is fully replaced if the local file defines it; `defaults.model` (was the flat `default_model:` key) sets the default model
- **meta.json cleanup on exit** — pid/port/owner cleared when CLI exits cleanly
- **Tools wired** — `pwsh`/`bash`, `file_view`, `file_write`, `file_str_replace`, `file_move`, `file_delete`, `quack` tools (ask_user, list_agents, switch_agent, spawn_subagent, use_skill, list_projects, switch_project); `use_skill` returns `# Skill`, `Skill-Path`, and full skill instructions in its tool result instead of appending them to the system prompt; `list_skills` removed — skills are listed in the system prompt
- **Agent definition loading** — `.agent.md` files from `~/.agents/` and project `.agents/`; well-known IDE files (`.github/copilot-instructions.md` → "Github Default", `CLAUDE.md`, `.cursor/rules`, `.github/agents/*.md`)
- **Agent validation on `/agent`** — unknown names rejected with suggestions
- **System prompt reload on agent/project switch** — prompt updated live in REPL loop
- **`/agent` listing** — discovers agents from global + project `.agents/` dirs and well-known IDE files
- **`/project` listing** — scans home directory for project roots (detected via `.git`, `.github`, `.agents`, `pyproject.toml`, etc.); shortest unique suffix names
- **Project path resolution** — partial/suffix matching (e.g. `quack-norris-3.0` or `3.0`); absolute paths also accepted
- **File tool CWD** — all file tools resolve relative paths against `meta.cwd`; factories bound to `get_cwd` lambda
- **Shell tool CWD** — `make_shell_tool(get_cwd)` factory; outside-CWD `cwd` arg forces `"human"` approval state; defaults to session project root (not `os.getcwd()`); LLM instructed not to prefix commands with `cd` and to omit `cwd` for project-root commands
- **Tool argument error hints** — `TypeError` on bad tool call arguments caught separately; returns structured message with expected vs received arguments so LLM can self-correct in the next iteration; missing required args detected before approval prompt is shown — invalid calls are auto-rejected with an actionable error, never shown to the user for approval
- **Relative path enforcement** — all path param descriptions strengthened to require relative paths (e.g. `foo/bar.py`), absolute only when outside project root; `Tool` base class gains `pre_execute_hook` / `post_execute_hook` slots (sync or async) called by `_execute` — generic extension point for tool authors; `attach_path_normalizer(tools, get_root)` in `files.py` wires both hooks: pre-hook rewrites absolute-path arguments to clean relative paths *before* approval check (so whitelist patterns match relative paths only, and the user sees `AGENTS.md` not `C:/…/AGENTS.md` in the approval prompt), post-hook strips the project root prefix from all `ToolResult.content` strings; path separator normalised to forward slashes in tool args; `_to_relative` only strips the root prefix, never touches non-path content args (no backslash corruption); `list_projects` shows `quack-norris-3.0 (.)` for the current project instead of a bare absolute path; applied to file tools, shell tool, and quack tools via their respective factories
- **CRLF normalisation** — `file_view` and `file_str_replace` normalise `\r\n` → `\n` on read so the LLM always sees plain LF line endings and `old_string` comparisons in `file_str_replace` work regardless of on-disk line endings (Windows CRLF files fully supported)
- **Agent loop resilience** — empty responses (no text, no tool calls) auto-retried with a synthetic nudge message injected into local history; emitted as `NudgeOutput` and persisted as a `system_hint` event so a replay stays in sync with the in-memory history
- **Per-message boundaries** — the agent loop emits `MessageEnd` after every assistant message (each loop iteration), not just at the end of a turn; the CLI allocates a `content_start`/`content_end` pair per message lazily, so a multi-tool turn produces several `content_end` events in chronological position rather than one lump at the end — this is what lets resume interleave text and tool calls correctly and lets checkpoints count messages
- **Session name auto-generation** — `cli/naming.py`'s `generate_session_name()`; one-shot LLM call after the first turn completes (only when `meta.name` is still unset and the session has been persisted); title shown in the session menu and via `--resume` picker; ephemeral non-interactive (`--prompt`) sessions are skipped since they're never persisted
- **Background tool execution** — shell commands still running after 30s are promoted to background processes instead of being killed; `tools/background.py` `ProcessRegistry` (session-scoped) holds `RunningProcess` instances with continuous stdout drain tasks; `shell.py` registers the live process and returns a `bg-xxxx` handle to the LLM; three auto-approved tools: `check_tool(handle)` polls buffered output, `await_tool(handle)` blocks until completion and returns full output + exit code, `kill_tool(handle)` terminates the process; renderer shows `⏳ still running — handle: bg-xxxx` for handle promotion messages; `ProcessRegistry` instantiated once per REPL session (parallel sessions don't share handles)
- **Sandbox worktrees** — `quack-norris-sandbox <branch> [path]` (`quack_norris/sandbox.py`); creates a git worktree (`git worktree add -B`, default location `../<repo>-<branch>`) and drops the user into an attached container shell with the worktree mounted at `/workspace`, so an AI agent can run isolated from the main checkout; image resolution: an explicit `--image` first, else an explicitly passed `--agent` (bundled image, warning on stderr that the worktree's Dockerfile is skipped), else the worktree's own `Dockerfile` (built as `sandbox-<branch>:latest`), else `sandbox.image` from config, else the bundled multi-stage `quack_norris/sandbox.Dockerfile` built with `--target <agent>` as `sandbox-<agent>:latest` (base = python:3.12-slim + curl/git/uv with `pipefail`; stages install quack-norris via `uv tool install`, the Devin CLI, or Claude Code via their official curl installers); agent chosen by `--agent quack|devin|claude` / `sandbox.agent`, default `quack`, and its host config is mounted for auth (`~/.quack-norris`; `~/.claude` + `~/.claude.json`; for Devin the login file `credentials.toml` from `$XDG_DATA_HOME/devin` → `/root/.local/share/devin/credentials.toml` plus `config.json`/`mcp_config.json` from `$XDG_CONFIG_HOME/devin` → `/root/.config/devin/`, all under `%APPDATA%\devin` on Windows, mounted per-file because that dir doubles as the Devin IDE's user-data dir); runtime from `--runtime` / `--docker` / `--podman` (mutually exclusive) / `sandbox.runtime`, else first of docker/podman on PATH; config mounts are read-write so the in-container agent can write sessions, and `--no-config` opts out; `--no-container` skips everything after the worktree creation and prints `cd <worktree>` (eval/`iex` it to move there, since a child process can't change the caller's directory), or runs `--shell` in the worktree on the host — for lightweight tasks
- **Attention bell** — `cli/notify.py`'s `bell()` writes a BEL (`\a`) to stderr whenever the CLI hands control back to the user: before an approval prompt (`interactive_approval`, skipped for whitelisted auto-approvals), before an `ask_user` question, and after an interactive agent turn finishes; no-op when stderr isn't a TTY or `QUACK_NO_BELL` is set; focus-awareness is delegated to the terminal emulator (Windows Terminal, iTerm2, kitty, GNOME Terminal only flash/notify on BEL when unfocused), so no window-handle polling or extra dependency

- **Real token counting** — context accounting uses a 4-chars-per-token proxy (`core/context.py`), not a tokenizer or the provider's reported `UsageInfo`; thresholds are therefore approximate and drift per model
- **TCP socket server** — Web UI relay (`cli/socket_server.py`); needed for WebUI integration
- **Pipeline decomposition** — multi-command approval cards for shell pipelines
- **WebUI server** — `quack_norris/webui/` module entirely missing
- **Image input (Part 3)** — `UserMessage` content parts (`TextPart`/`ImagePart`), OpenAI + Bedrock encoder updates, base64 loading in `_try_image_path`, session log parts storage, history reconstruction
